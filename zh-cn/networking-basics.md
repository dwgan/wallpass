# 网络基础：数据如何从 A 到 B

当你打开一个网站时，一秒钟之内会发生几十个看不见的步骤。本页解释这些基础概念：什么是 IP 地址、域名如何变成数字、数据如何跨越全球传输，以及 HTTPS 究竟保护了什么。本页面向零基础读者，不需要任何网络知识。

## 客户端与服务器

你的电脑是**客户端**：它负责发出请求。存放网站的机器是**服务器**：它负责应答。互联网上几乎一切都遵循这个模式——客户端发送请求，服务器返回响应。

## IP 地址与端口

每一台联网设备都需要一个地址，就像房子需要门牌号一样。这就是**IP 地址**。例如 `93.184.216.34` 是一个 IPv4 地址；IPv6 地址更长，例如 `2606:2800:220:1:248:1893:25c8:1946`。

一台服务器可以同时运行多个服务，所以还需要**端口**来区分它们。端口 `80` 是未加密网页流量（HTTP）的默认端口，端口 `443` 是加密网页流量（HTTPS）的默认端口。一个「地址 + 端口」的组合——例如 `93.184.216.34:443`——唯一指定一个服务。

## DNS：把名字变成数字

人记名字，电脑记数字。**域名系统（DNS）**就是互联网的电话簿：它把 `example.com` 翻译成 IP 地址。当你在地址栏输入一个网址时，你的电脑会先问 DNS 解析器「这个域名的 IP 地址是什么？」，然后才去连接那个地址。

## 数据包与路由

数据并不是一整条连续流。它会被切成一个个小块，称为**数据包**，每个数据包携带源地址、目标地址和一部分负载。**路由器**像邮局一样，把每个数据包从一个网络转发到下一个网络，直到到达目的地。

<pre class="mermaid">

    A[你的电脑] --> B[家庭路由器]
    B --> C[你的 ISP]
    C --> D[骨干路由器]
    D --> E[服务器的数据中心]
    E --> F[网页服务器]
</pre>

## TCP 与 UDP

两种常见的数据传输方式：

- **TCP** 保证送达和顺序。如果数据包丢失，TCP 会重新发送。网页浏览、电子邮件和文件传输使用 TCP。
- **UDP** 更快，但不做任何保证：数据包可能迟到、乱序甚至丢失。视频通话、游戏和 DNS 查询经常使用 UDP。

## HTTP 与 HTTPS

**HTTP** 是客户端和网页服务器之间交流的语言：`GET /index.html` 表示请求某个页面。但 HTTP 本身是明文——路径上的任何人都能读到请求内容。

**HTTPS** 把 HTTP 包在 **TLS**（传输层安全协议）里面。连接被加密，中间人无法读取你请求和响应的内容。

不过，加密不等于隐身。即使使用 HTTPS，网络观察者仍然可以看到：

- 你连接的 IP 地址和使用的端口，
- 数据传输的时间和流量大小，
- 你发出的 DNS 查询，
- 以及——在 TLS 握手期间——**SNI** 字段中的域名。

这些可见的「元数据」很重要：下一页会解释防火墙是如何利用这些信息来阻断流量的。
