# GFW 是如何工作的

## 它是什么

**GFW（Great Firewall）**是人们对位于中国大陆网络与境外互联网之间的一系列过滤系统的通称。它的目标是限制对特定网站和服务的访问。理解它是如何阻断流量的，也就知道了一个可行的绕过方案需要做到什么。

## 观察者能看到什么

根据上一页的内容，即使 HTTPS 流量是加密的，元数据仍然暴露在外。一个监视连接的防火墙可以看到：

- 目标的 **IP 地址**和**端口**，
- 针对域名的 **DNS 查询**，
- 数据包的时间和大小，
- TLS 握手时的 **SNI** 字段（通常包含域名），
- 任何未加密流量的明文内容。

这些信息都可以用来做出阻断决定。

## 阻断手段

**1. IP 黑名单。** 被屏蔽服务的已知 IP 地址或整个地址段被直接不路由，或到这些地址的连接被丢弃。这种方法比较粗糙：它会阻断托管在这些地址上的所有内容。

**2. DNS 污染。** 防火墙针对被屏蔽域名的 DNS 查询返回一个假 IP 地址。客户端连上假地址后什么都得不到，网站看起来就像无法访问。

**3. TCP RST 注入。** 为了中断一个活跃连接，路径上的攻击者可以发送一个伪造的 TCP **RST** 包，让它看起来像是来自通信双方之一。两端都会认为连接「已关闭」而放弃。

**4. 基于 SNI 的过滤。** 客户端开始 TLS 连接时，会在加密开始之前把域名放在 SNI 字段里发送。防火墙可以读取该字段并注入重置包——于是与被屏蔽域名的连接在握手阶段就死掉了。

**5. 深度包检测。** 对于未加密的流量，防火墙可以直接读取负载，并阻断包含被过滤关键词的请求。

## 这对绕过意味着什么

一个可行的绕过方案需要三样东西：

1. 一台**位于防火墙之外的服务器**——被屏蔽的内容在那里获取，因为那里可以访问；
2. **加密**——这样你的流量内容就无法被读取或进行关键词过滤；
3. **看起来不像被屏蔽的流量**——否则防火墙会直接认出这个连接并重置它。

第三点是最难的部分。仅仅加密连接是不够的，如果防火墙仍然能看到目标 IP 或读取 SNI 字段。下一页会解释代理和隧道是如何同时解决这三点的。
